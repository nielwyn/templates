HALO — Branding & Web Studio Template

HALO is a single-page, animation-forward template built for branding studios, freelancers, consultants and small businesses who want a site that feels custom-built. It's still plain HTML/CSS/JavaScript — no build step, no npm install — but unlike a zero-dependency template, it loads two small libraries from a CDN to drive the motion and the 3D hero object. Read the dependencies section below before you ship.

What's included

  • index.html — the full one-page site
  • css/style.css — the entire design system (dark theme, CSS variables)
  • js/main.js — preloader, custom momentum cursor, mobile nav, hero showcase deck, case-study modal, Brand Lab, work carousel, process stepper, scope estimator, hero deck tilt, demo form and toasts, graceful fallback if the CDN libraries fail to load. Each feature is its own numbered, commented block; the file header lists them.
  • js/animations.js — GSAP/ScrollTrigger: the hero intro (fires when the preloader finishes), hero scroll-parallax, scroll reveals, counting stats, the Services active-row spotlight, the About pull-quote's decode-text reveal, the CTA's scale-in entrance, the footer's parallax wordmark
  • js/scene.js — the Three.js hero particle field
  • images/favicon.svg
  • documentation/documentation.html — this guide
  • README.txt, LICENSE.txt, CHANGELOG.txt

Getting started

Open index.html directly in a browser, or serve it locally:

# Node / bun
bunx serve .

# or Python
python3 -m http.server 8080
This template needs an internet connection to preview — the fonts and the two libraries below load from a CDN. This is normal for templates that use GSAP/Three.js and is not something you need to "fix".

Dependencies (important)

Unlike a fully static template, HALO loads two libraries via plain <script> tags at the bottom of index.html — no bundler, no install step, but they are real runtime dependencies:

LibraryUsed forLoaded from
GSAP 3.12.5 + ScrollTriggerHero intro and scroll-parallax, scroll reveals, counting stats, the Services spotlight, the decode-text pull-quote, the footer wordmarkjsDelivr CDN
Three.js 0.134.0The rotating hero objectjsDelivr CDN

Both are loaded with pinned version numbers so the site won't silently break from an upstream update. If you'd rather self-host them, download the same files and point the <script src> tags in index.html at your own copies.

The page is built to degrade gracefully: if either library fails to load (offline, blocked CDN, ad blocker), main.js force-reveals all content after ~1.2s so the page is still fully readable — you just lose the animation and the 3D object (a soft CSS glow stands in for it, see .hero-scene-fallback).

Interactive sections

Everything below is plain JavaScript in js/main.js, wired to the markup through data-* attributes rather than IDs, so you can move or restyle the markup without touching the script. Each block null-checks its own elements: delete a section from index.html and the rest of the page keeps working.

Hero showcase deck

The large featured card in the hero (#stageMainCard) carries a data-project value, and the segmented buttons below it carry data-stage. Clicking a button swaps the featured project in place; clicking the card opens the case-study modal for whichever project is currently featured. To change which three projects appear, edit the data-stage buttons and make sure each value matches a data-project key used by the work cards.

Case-study modal & brand asset inspector

Opens from any .work-card or from the hero deck. Its four panels are driven by data-tab (strategy, system, deliverables, review) on buttons marked up with role="tab" and aria-selected; the dialog itself carries role="dialog", aria-modal="true" and aria-labelledby.

It closes on Escape, on a click on the backdrop, and on the close button. The prev/next buttons cycle projects without closing, and the left/right arrow keys do the same while it is open — both wrap around at the ends. Its "Inquire" button closes the modal, prefills the contact textarea with a sentence naming the case study you were just reading, scrolls to the contact section and focuses the field, so a visitor never has to retype what caught their eye.

To add a project: add a .work-card with a new data-project value and a matching entry in the PROJECTS_DATA object in js/main.js. The copy for all four tabs, the palette swatches and the ordering (PROJECT_ORDER) all live there — there is no CMS and no fetch.

Brand Lab

The #lab section crosses four creative directions (data-vibe: kinetic, minimal, editorial, brutalist) with four palettes (data-palette: amber, quartz, clay, mineral) and re-renders the preview card for the selected combination. The type treatments and color values for each option live in the LAB_CONFIGS object in js/main.js; add an option by adding a button with a new value and a matching key under LAB_CONFIGS.vibes or LAB_CONFIGS.palettes.

This is a genuine selling device for a studio — it lets a prospect feel the range of your work in ten seconds. If it isn't right for you, delete the <section id="lab"> block and its nav link.

Selected Work carousel

The work section shows one project at a time. Prev/next (#workPrev / #workNext) and a generated row of dots toggle an .is-active class between the cards rather than scrolling a track, so a card is never half-clipped at the edge of a viewport. The prev/next buttons disable themselves at the first and last card — it does not wrap. The dots are built from the cards themselves and take their accessible labels from each card's <h3>, so adding a project needs no change to the controls.

It deliberately does not use GSAP, so it keeps working if the CDN is blocked. Project visuals are pure CSS and inline SVG; see Customization for swapping in real screenshots.

Process stepper

The #process timeline uses data-step (0–3) on each step card, with a detail panel showing that step's deliverables. On narrow viewports the panel is moved inside the selected card rather than left below the timeline, so the selection and its detail stay together. Edit the step copy directly in index.html and the deliverables lists in the PROCESS_STEPS array in js/main.js.

Scope & timeline estimator

In the contact section, scope chips (data-scope) are multi-select and timeline chips (data-timeline) are single-select; the selection is summarized for the inquiry. The values are read straight from the attributes, so renaming a service is a one-word edit in the markup.

Custom cursor

The momentum cursor activates only on devices that report real hover support, and only when prefers-reduced-motion is not set. Any element you want it to react to gets data-cursor-hover. To remove the cursor entirely, delete its block from js/main.js and the .cursor rules from css/style.css; the data-cursor-hover attributes then do nothing and can be left in place.

Customization

Rebranding

"HALO" appears as plain text in index.html — in the nav brand, hero, footer and the title/meta tags. Find-and-replace it with your own name; there's no logo image to redraw.

Colors

:root {
  --bg: #15101a;
  --accent: #ffc53d;
  --accent-2: #ff7a68;
  --ink: #f6f1e9;
}

These variables in css/style.css drive the whole palette, including the 3D particle field's colors (set separately in js/scene.js — edit the PALETTE array near the top of the file to match).

Fonts

Headings use Unbounded, body text uses Hanken Grotesk, both free Google Fonts loaded in the <head>. Swap the Google Fonts <link> and the --font-display / --font-body variables to change them.

The 3D hero object

js/scene.js builds a full-bleed, centered field of drifting colored points (THREE.Points) rather than a single positioned object (a sphere, a ring, a letterform). That's a deliberate choice, not just a style preference: a discrete object has to sit offset to one side of the headline, and a fixed world-space offset combined with Three.js's perspective projection scales differently from percentage-based CSS as the viewport width changes — the object and any CSS glow behind it drift out of sync on resize. A centered, symmetric field has nothing offset to one side, so there's nothing that can misalign. If you add a positioned object of your own, test it at several widths before shipping, or keep it centered the way this one is.

To change the look, edit COUNT (how many points), PALETTE (their colors) or the spread ranges in the position-generation loop near the top of the file. To remove the 3D background entirely, delete the <script src="js/scene.js"> tag — the CSS glow behind it (.hero-scene-fallback) still gives the hero some depth on its own.

Work gallery images

The project cards use CSS gradients (--c1/--c2 custom properties per card) instead of photography, so the template ships with zero bundled images to license. Swap in your own project screenshots by replacing .work-visual with an <img> once you have real work to show.

Performance & accessibility

  • The 3D scene caps its pixel ratio at 2x and pauses rendering when the tab isn't visible.
  • Everything respects prefers-reduced-motion: the custom cursor, the marquee strip, the hero deck tilt, the decode-text reveal and every scroll animation in animations.js turn off, and the page shows fully revealed, static content instead — including the counting stats, which render their final number immediately rather than starting at 0 with no way to count up. The reveal and marquee overrides are in a @media (prefers-reduced-motion: reduce) block in css/style.css, so they hold even if JavaScript never runs.
  • The custom cursor only activates on devices that report real hover support, so it won't interfere with touch.
  • None of the interactive sections depend on GSAP or Three.js: the hero deck, the case-study modal, the Brand Lab, the work carousel, the process stepper and the estimator are all plain JavaScript in js/main.js, so they keep working if the CDN is blocked. What you lose in that case is the scroll animation and the 3D field, not the functionality.
  • The work carousel swaps cards with a class toggle and has no scroll-linked layout reads, so adding projects costs you nothing in frame time.
  • The hero deck's 3D perspective tilt reads getBoundingClientRect() on mouse move and is gated behind both prefers-reduced-motion and (hover: hover), so it never runs on touch devices. It is the only tilt effect in the template — the work cards do not tilt.

Wiring up forms

The contact form is demo-only as shipped. It validates its fields and shows a success toast, but the submission is not sent anywhere. Connect it before you launch or you will lose every inquiry.

The form is marked with data-demo-form, which is what tells js/main.js to intercept the submit and fake the result. To make it real, remove that attribute and give the form an action:

<!-- Formspree, Netlify Forms, Basin, your own endpoint — all the same shape -->
<form class="contact-form" action="https://formspree.io/f/YOUR_FORM_ID" method="POST">

With data-demo-form gone the browser submits the form normally and the toast no longer fires, so the service's own confirmation page is what the visitor sees. If you would rather keep the toast and the in-page experience, leave the attribute off and post from your own fetch() in its place — and handle the failure branch, so a lost inquiry is visible to the visitor instead of silent.

The scope and timeline chips are plain buttons, not inputs. If you want their values submitted, add a hidden input and write the current selection into it when a chip is clicked.

Browser support

Tested in the latest Chrome, Firefox, Safari and Edge. The 3D hero needs WebGL — essentially every browser released in the last decade has it, but very old or locked-down browsers may fall back to the CSS glow only, which is an intentional, graceful fallback rather than a bug.
