Narra — Boutique Editorial Sales Page Template

Narra is a long-form editorial sales page for boutique agency owners, independent consultants, executive coaches and personal brands selling high-ticket retainers. Version 1.2.0.

It ships two ways: a prebuilt page you can open and host immediately, and the React source project it was built from. Read the next section before you decide which one you're working with.

Dependencies — read first

Narra's editable source is a React 19 + TypeScript + Vite 8 + Tailwind CSS 4 project. That means there is a build step: to change the page you edit files in source/, run a build, and that produces the static page.

If you don't want to run a build step: use dist/ as-is. It is a finished static page — HTML, one CSS file, one JS file and the images. You can host it anywhere and edit its text directly if you're comfortable in built markup, but the built files are minified, so real editing belongs in source/.

If you want to customize properly: you need Node.js installed and you'll run two commands. Requirements and steps are in Getting started.

RequirementVersion
Node.js^20.19.0 or >=22.12.0 (required by Vite 8)
Tested onNode v24.14.1, npm 11.11.0

A package-lock.json is included, so npm install installs the exact dependency versions this release was built and tested with. You should not need --force or --legacy-peer-deps; if you do, something is wrong — email support rather than forcing it.

Getting started

Just look at it

Open dist/index.html in any modern browser. Nothing to install.

Edit it

cd source
npm install        # once
npm run dev        # live preview; open the URL it prints

Edit any file under src/ and the browser updates. When you're happy:

npm run build      # writes source/dist/
npm run lint       # optional: TypeScript check (tsc --noEmit)

Then copy the contents of source/dist/ over the top-level dist/ folder — that folder is what you upload to your host.

vite.config.ts sets base: './', which makes the build use relative asset paths. That's what lets dist/index.html work both when opened directly from your filesystem and when served from a subfolder on your host. If you move the site to a domain root you can leave it exactly as it is.

Editing the copy

Text lives in two places:

  • src/data/content.ts — the repeating, data-shaped copy: CURRICULUM_PHASES, CASE_STUDIES, FAQ_ITEMS and VAULT_ASSETS. Add, remove or reorder array entries and the page follows. The shape of each entry is defined in src/types.ts, so your editor will tell you if a field is missing.
  • The component files — headlines, paragraphs and button labels are written inline in the relevant component under src/components/. Use the section table above to find the file.

Page title, meta description and social preview tags are in source/index.html, not in a component. Update them before you launch — they still say "Narra".

All names, testimonials, revenue figures and prices in the template are fictional demonstration copy. Replace every one of them. Do not publish someone else's case-study numbers as your own.

The four presets

Narra Linen & Cedar is the default (it is :root). The other three are override blocks further down src/index.css: 

[data-theme="olive"]       { /* Tuscan Olive & Clay */ }
[data-theme="noir"]        { /* Obsidian & Gold */ }
[data-theme="terracotta"]  { /* Terracotta Silk */ }

They're applied by setting data-theme on <html>. To ship one as your permanent look, change the initial state in src/App.tsx: 

const [theme, setTheme] = useState<ThemeMode>('noir');

To build your own, copy one of the blocks, rename it, and add the name to the ThemeMode union in src/types.ts.

Fonts

Narra uses Fraunces for headings and Plus Jakarta Sans for body text, both loaded from Google Fonts by a <link> in source/index.html. They are not bundled, so the page needs a network connection to render in its intended typography — offline it falls back to Georgia and your system sans-serif.

To swap them: change the Google Fonts URL in source/index.html, then update the two stacks in src/index.css:

--font-serif: "Your Display Font", Georgia, serif;
--font-sans:  "Your Body Font", system-ui, sans-serif;

Headings get the serif stack through a single rule (h1, h2, h3, h4, .font-serif-editorial), so you don't need to touch components. Apply class="font-serif-editorial" to put the display face on anything else.

Images

Four photographs ship in src/assets/images/. They are AI-generated placeholders — see LICENSE.txt. Replace them with your own photography before launch; a sales page whose portrait isn't the person it names misleads your visitors.

To replace one, drop your file into src/assets/images/ and update the import at the top of the component that uses it. Vite hashes and copies imported images automatically, so there's no path to configure.

The bundled JPEGs are large — roughly 700–890 KB each, about 3.1 MB total — because they're full-resolution placeholders. Before you launch, export your replacements as WebP or AVIF at the size they actually display. It is the single biggest thing you can do for your page speed score.

Wiring up the audio player

The audio player is demo-only as shipped. It animates a waveform and advances a progress bar on a timer. There is no <audio> element behind it and no audio file is included.

To make it real, open src/components/AudioSamplePreview.tsx, put your file in src/assets/, and drive the existing state from a real audio element instead of the interval: 

import { useState, useRef, useEffect } from 'react';
import excerpt from '../assets/masterclass-excerpt.mp3';

export default function AudioSamplePreview() {
  const [isPlaying, setIsPlaying] = useState(false);
  const [progress, setProgress] = useState(0);
  const audioRef = useRef<HTMLAudioElement>(null);

  // Replace the existing setInterval effect with this:
  useEffect(() => {
    const el = audioRef.current;
    if (!el) return;
    const onTime = () => setProgress((el.currentTime / el.duration) * 100 || 0);
    const onEnd = () => { setIsPlaying(false); setProgress(0); };
    el.addEventListener('timeupdate', onTime);
    el.addEventListener('ended', onEnd);
    return () => {
      el.removeEventListener('timeupdate', onTime);
      el.removeEventListener('ended', onEnd);
    };
  }, []);

  // And make the existing play/pause button call this instead of setIsPlaying alone:
  const toggle = () => {
    const el = audioRef.current;
    if (!el) return;
    if (isPlaying) { el.pause(); } else { void el.play(); }
    setIsPlaying(!isPlaying);
  };

  // Render this alongside the existing markup:
  // <audio ref={audioRef} src={excerpt} preload="metadata" />
}

The waveform bars and the progress fill already read from progress, so they start tracking real playback as soon as the effect above replaces the timer. Keep the duration label in the markup honest — it's hardcoded to 04:12.

If you'd rather not ship audio at all, delete <AudioSamplePreview /> from src/App.tsx and remove the component file.

Wiring up the application form

The application drawer is demo-only as shipped. It validates its inputs and advances to an "Application Received" screen, but the submission is not transmitted anywhere. Connect it before you launch, or you will lose every lead.

Open src/components/ApplicationDrawer.tsx. The step-2 form's onSubmit={handleNext} is where the data should leave the page. Pick one:

Formspree (no backend)

const handleNext = async (e: React.FormEvent) => {
  e.preventDefault();
  if (step === 1) { if (validateStep1()) setStep(2); return; }

  await fetch('https://formspree.io/f/YOUR_FORM_ID', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
    body: JSON.stringify(formData),
  });
  setStep(3);
};

Netlify Forms

Netlify detects forms in the built HTML, and this form is rendered by React, so add a hidden static form to source/index.html for detection and post to it: 

<!-- in source/index.html, inside <body> -->
<form name="application" netlify hidden>
  <input type="text" name="name" />
  <input type="email" name="email" />
  <textarea name="message"></textarea>
</form>
// then in handleNext:
await fetch('/', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: new URLSearchParams({ 'form-name': 'application', ...formData }).toString(),
});
setStep(3);

Your own endpoint

Same shape — fetch your URL with JSON.stringify(formData). Whichever you choose, handle the failure case: wrap the await in try/catch and show an error state instead of the confirmation screen, so a lead never silently disappears.

The drawer is opened by onApplyClick, which is passed to the nav, hero, curriculum, pricing and footer. If you replace it with a Calendly or Typeform link, change the handler once in src/App.tsx and every call-to-action follows.

Removing the colorway switcher

The floating "Colorway" pill at the bottom right is a preview aid for choosing a theme, not part of the sales page. Once you've picked one:

  1. Set your choice as the initial theme state in src/App.tsx.
  2. Delete the <TemplateCustomizer ... /> element and its import.
  3. Delete the onCustomizeClick prop from <TopBar /> and the button that uses it in TopBar.tsx.
  4. Delete src/components/TemplateCustomizer.tsx and the isCustomizerOpen state.

Rebuild. Nothing else depends on it.

Deploying

Upload the contents of dist/ to any static host — Netlify, Vercel, Cloudflare Pages, GitHub Pages, S3, or plain cPanel/FTP. There is no server-side component, no database and no environment variable to set.

If your host builds from a Git repository instead, point it at source/ with build command npm run build and publish directory dist.

Browser support

Current versions of Chrome, Firefox, Safari and Edge, on desktop and mobile. The layout is responsive from 360 px up. The build targets modern browsers that support ES modules; Internet Explorer is not supported.
