Narra — Boutique Editorial Sales Page

A long-form editorial sales page for consultants, coaches and boutique studios selling high-ticket retainers. Version 1.2.0.

Getting started

To view or host it: open dist/index.html, or upload the contents of dist/ to any static host. Nothing to install.

To edit it: the source is a React + TypeScript + Vite + Tailwind 4 project, so there's a build step. You need Node ^20.19 or >=22.12 (required by Vite 8; tested on v24.14.1).

cd source
npm install
npm run dev      # live preview
npm run build    # writes source/dist/
npm run lint     # TypeScript check

Then copy source/dist/ over the top-level dist/ — that's what you upload. A package-lock.json is included, so you should never need --force or --legacy-peer-deps.

vite.config.ts sets base: './' so the build uses relative paths. That's what lets dist/index.html work when opened straight from your filesystem. Leave it as it is.

The page is ten sections — hero, core tension, 4-pillar method, curriculum tabs, deliverables vault, audio preview, case studies, mentor story, pricing, FAQ — plus a sticky nav, footer and the application drawer. All of it is composed in src/App.tsx, one line per section, each named after its component file. Delete a line to drop a section; move it to reorder. Nothing else needs changing.

Editing the copy

  • src/data/content.ts — the repeating copy: CURRICULUM_PHASES, CASE_STUDIES, FAQ_ITEMS, VAULT_ASSETS. Add or remove array entries and the page follows. Shapes are in src/types.ts, so your editor will flag a missing field.
  • The component files — headlines, paragraphs and button labels are inline in each component under src/components/.
  • source/index.html — page title, meta description and social preview tags. These still say "Narra"; update them before launch.

Every name, testimonial, revenue figure and price in the template is fictional demo copy. Replace all of it — don't publish someone else's case-study numbers as your own.

Colors & colorways

Every color is a CSS variable declared once in :root in src/index.css. Change it there and it propagates everywhere.

Linen & Cedar is the default — it is :root. The other three are override blocks further down the same file, applied via data-theme on <html>:

[data-theme="olive"]       /* Tuscan Olive & Clay */
[data-theme="noir"]        /* Obsidian & Gold */
[data-theme="terracotta"]  /* Terracotta Silk */

The floating "Colorway" pill at the bottom right is a preview aid, not part of the page. Once you've picked one, set it as the initial state in src/App.tsx — useState<ThemeMode>('noir') — then delete <TemplateCustomizer />, its import, and the onCustomizeClick prop on <TopBar />. To build your own colorway, copy a block, rename it, and add the name to ThemeMode in src/types.ts.

Fonts

Fraunces (headings) and Plus Jakarta Sans (body) load from Google Fonts via a <link> in source/index.html, so the page needs a connection to render in its intended typography — offline it falls back to Georgia and your system sans.

To swap: change that URL, then the two stacks in src/index.css. Headings pick up the serif through one rule (h1, h2, h3, h4, .font-serif-editorial), so you don't touch components. Add class="font-serif-editorial" to put the display face on anything else.

Images

Four WebP photographs in src/assets/images/, about 424 KB total. They are AI-generated placeholders (see LICENSE.txt) — replace them with your own photography before launch.

Drop your file into that folder and update the import at the top of the component that uses it; Vite hashes and copies it automatically. Keep the width/height attributes on the <img> accurate to your new file so the layout doesn't shift, and export at roughly the size it displays.

The audio player

Demo-only as shipped. It animates a waveform on a timer. There is no <audio> element and no audio file is included.

To make it real, put your file in src/assets/ and, in src/components/AudioSamplePreview.tsx, drive the existing progress state from a real audio element instead of the interval:

import excerpt from '../assets/masterclass-excerpt.mp3';

const audioRef = useRef<HTMLAudioElement>(null);

// replaces the setInterval effect
useEffect(() => {
  const el = audioRef.current;
  if (!el) return;
  const onTime = () => setProgress((el.currentTime / el.duration) * 100 || 0);
  const onEnd  = () => { setIsPlaying(false); setProgress(0); };
  el.addEventListener('timeupdate', onTime);
  el.addEventListener('ended', onEnd);
  return () => {
    el.removeEventListener('timeupdate', onTime);
    el.removeEventListener('ended', onEnd);
  };
}, []);

// the play/pause button calls this
const toggle = () => {
  const el = audioRef.current;
  if (!el) return;
  isPlaying ? el.pause() : void el.play();
  setIsPlaying(!isPlaying);
};

// render alongside the existing markup
<audio ref={audioRef} src={excerpt} preload="metadata" />

The waveform and progress fill already read progress, so they start tracking real playback immediately. The duration label is hardcoded to 04:12 — update it. Don't want audio at all? Delete <AudioSamplePreview /> from src/App.tsx.

The application form

Demo-only as shipped. The drawer validates and shows a confirmation, but the submission goes nowhere. Connect it before you launch or you'll lose every lead.

In src/components/ApplicationDrawer.tsx, handleNext is where the data should leave the page:

const handleNext = async (e: React.FormEvent) => {
  e.preventDefault();
  if (step === 1) { if (validateStep1()) setStep(2); return; }

  try {
    await fetch('https://formspree.io/f/YOUR_FORM_ID', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
      body: JSON.stringify(formData),
    });
    setStep(3);
  } catch {
    // show an error state — never let a lead vanish silently
  }
};

Any endpoint works the same way. For Netlify Forms, add a hidden static copy of the form to source/index.html (Netlify scans the built HTML, and this form is rendered by React) and post to / with 'form-name': 'application' in a URLSearchParams body.

The drawer opens via onApplyClick, passed to the nav, hero, curriculum, pricing and footer — so if you'd rather send people to Calendly or Typeform, change that one handler in src/App.tsx and every call-to-action follows.

Deploying

Upload the contents of dist/ to any static host — Netlify, Vercel, Cloudflare Pages, GitHub Pages, S3, cPanel. No server, no database, no environment variables. If your host builds from Git instead, point it at source/ with build command npm run build and publish directory dist.

Works in current Chrome, Firefox, Safari and Edge, responsive from 360 px up. The build targets browsers with ES module support; IE is not supported.
